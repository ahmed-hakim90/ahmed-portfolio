# UX Rules — Ahmed Portfolio

1. Start from the user's goal, fastest successful path, prior/next step, permissions, and failure recovery.
2. Preserve business requirements while correcting avoidable friction; validate uncertain rules before implementation.
3. Make one primary action clear and keep secondary actions subordinate and contextual.
4. Design loading, empty, error, offline/network, disabled, read-only, success, stale, partial, and permission-denied states.
5. Prefer inline feedback for validation and persistent issues; reserve toasts for transient confirmation.
6. Choose page, drawer/sheet, modal, or popover according to workflow depth and screen size.
7. Mobile layouts must reprioritize—not merely shrink. Avoid horizontal scrolling except for inherently wide data.
8. RTL/LTR verification includes navigation, arrows, breadcrumbs, drawers, inputs, pagination, tables, charts, and mixed-direction content.
9. Accessibility is part of definition of done: semantics, headings, labels, focus order, keyboard use, contrast, names, and touch targets.
10. Investigate root cause before adding a UI workaround, local override, duplicate state, or new dependency.

## Product-specific emphasis

For this content/marketing experience, favor task clarity, trustworthy feedback, concise hierarchy, and preservation of user context across the primary flow.
